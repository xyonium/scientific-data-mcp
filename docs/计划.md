# scientific-data-mcp 计划

> 科研**结构化数据** MCP —— 化合物 / 生物活性 / 蛋白序列 / 蛋白结构 / 基因 / 文献 免费官方 API 直连。
> 与 finance-mcp（金融）、paper-search（文献检索 OpenWebUI 工具）互补，不做重复。

> **状态（2026-11-20）**：M1–M4 已实现；最新已发布 v0.12.0，v0.13.0（24 个基础工具；含 WHO GHO、STRING、openFDA、ClinicalTrials.gov、AlphaFold DB、Open Targets、Reactome、NCBI Gene、ClinVar、InterPro、QuickGO、HPO、GEO、KEGG、DailyMed、GDC、cBioPortal、GTEx、Ensembl、ChEBI、BindingDB；Materials Project key 加 1 个，BioGRID key 解锁交互 source；同类 I/O 已合并）已完成，进入发布流程；K-Dense database-lookup v1.8 的 80 库已快照并加季度扫描；错误契约加入上游漂移信号。
> 本文件保留为历史规划；当前口径以 `README.md` 与
> `docs/superpowers/specs/2026-11-17-scientific-data-mcp-design.md` 为准。

## 定位与边界

| 项目 | 域 | 关系 |
|------|----|------|
| finance-mcp | 金融/宏观行情 | 兄弟项目，复用其 provider/tool/容器模式 |
| paper-search | 学术**文献**检索 + RAG 入 OpenWebUI | 兄弟项目；本项目不重复做文献搜索（仅在有官方免 key 结构化 API 时提供**文献元数据**查询，如 pubmed 记录） |
| **scientific-data-mcp** | 科研**实体数据**：chem/bio/结构/基因/临床/材料/天文 | 本项目 |

## 动机

背景：2026-09-13 finance-mcp kimi 去重工作（R0–R17）中发现 kimi datasource 把大量**本来就免 key 的官方科研 API** 包装成收费额度源（pubchem/chembl/uniprot/pdb/pubmed 全部实测是 1:1 官方 REST 转发）。这些源与金融无关，从 kimi 摘除后需要一个落点。

## 技术形态（复用 finance-mcp 模式）

- Python + FastMCP，provider 层（每源一个 `providers/<name>.py`）+ tool 层（`tools/<domain>.py` 路由链）
- 全部源**免 key 或免费注册 key**；key-gated 源遵循"有 key 自动启用、无 key 静默跳过"（paper-search 同款约定）
- docker 部署，mcpo 暴露 OpenAPI（与 finance-mcp/futu-opend-mcp 同管路）
- 测试：respx hermetic 全套（0 egress 证明），`live_sources.py` 式 per-source smoke 脚本
- 反幻觉 docstring 纪律（finance-mcp 2d4892f 先例）：quote/lookup 类工具写明"只返回 API 真实响应，不补全"

## 与 paper-search 的边界规则

**一句话：paper-search 管"找论文/读论文/入 RAG"，本项目管"查实体数据"。**

- 用户问"这个化合物的性质/靶点" → 本项目 pubchem/chembl
- 用户问"这个蛋白的序列/结构" → 本项目 uniprot/pdb
- 用户问"关于 X 的论文" → paper-search
- 用户给了一个 PMID 想要结构化记录（不下载全文） → 本项目 pubmed E-utilities efetch 可用；要全文要入库 → paper-search
